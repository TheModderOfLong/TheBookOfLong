# 完整功能说明

本文按龙之书运行流程说明当前完整功能。快速制作第一个 Mod 可以先看 [快速入门](快速入门.md)。

## 1. 总体流程

龙之书启动后会完成这些工作：

1. 初始化配置界面。
2. 初始化原始数据导出。
3. 扫描 `ModsOfLong` 中的数据 Mod。
4. 读取 Mod 加载配置。
5. 读取 CSV 补丁并解析 `modXXX` 符号 ID。
6. 读取复杂 JSON 补丁。
7. 注册 Harmony 补丁。
8. 游戏加载配置表时导出原始文本，并注入 CSV 补丁。
9. 游戏场景对象就绪后，先导出原始复杂对象 JSON，再注入复杂 JSON 补丁。

关键顺序：

- CSV 文本补丁发生在游戏读取 `TextAsset.text` 的链路上。
- ComplexData 补丁发生在 `GameController.Start` 之后，等待目标控制器对象就绪。
- ComplexData 会先导出原始对象，再应用 Mod 补丁，避免导出结果被补丁污染。

## 2. 配置界面

默认行为：

- 进游戏后自动弹出一次。
- 默认按 `F4` 打开或关闭。
- 设置会写入 MelonPreferences 配置。

当前设置分类：

```text
TheBookOfLong_UI
```

当前设置项：

```text
toggle_key
auto_open_on_startup
auto_open_delay_seconds
```

## 3. 原始数据导出

导出根目录：

```text
<游戏目录>\DataDump\Latest
```

文本配置导出目录：

```text
<游戏目录>\DataDump\Latest\Data
```

同时会生成：

```text
<游戏目录>\DataDump\Latest\manifest.json
```

导出策略：

- 尽量保留游戏原始 `TextAsset` 文本。
- CSV 按原始文本导出。
- `PoetryData` 保持 JSON 文本导出。
- 文本统一写为 UTF-8 无 BOM。
- 不再导出旧版 `GameDataCsv.csv`。

## 4. 数据 Mod 目录

数据 Mod 根目录：

```text
<游戏目录>\Mods\ModsOfLong
```

典型结构：

```text
ModsOfLong
└─ modExample
   ├─ Info.json
   ├─ Data
   │  └─ *.csv
   └─ ComplexData
      └─ *.json
```

识别规则：

- 只有 `mod` 开头的文件夹会被识别为数据 Mod。
- `Info.json` 可选。
- `Data` 存放 CSV 补丁。
- `ComplexData` 存放复杂 JSON 补丁。

`Info.json` 示例：

```json
{
  "Name": "示例 Mod",
  "Version": "1.0.0"
}
```

## 5. Mod 加载配置

加载配置文件：

```text
<游戏目录>\UserData\TheBookOfLong.ModLoadConfig.json
```

示例：

```json
{
  "FormatVersion": 1,
  "Description": "修改本文件后，需要完全重启游戏才能应用新的 Mod 加载配置。Mods 数组中的顺序就是加载顺序，越靠后覆盖能力越强。",
  "Mods": [
    {
      "FolderName": "modExample",
      "DisplayName": "示例 Mod",
      "Version": "1.0.0",
      "Enabled": true
    }
  ]
}
```

规则：

- `Mods` 数组顺序就是加载顺序。
- 越靠后的 Mod 越晚加载，因此覆盖能力越强。
- `Enabled` 为 `false` 时，该 Mod 不参与当前启动流程。
- 修改后需要完全重启游戏。

## 6. CSV 补丁

补丁目录：

```text
Mods\ModsOfLong\modExample\Data
```

匹配规则：

- 补丁文件按导出的资源路径匹配。
- 补丁文件可以带 `.csv` 扩展名。
- 运行时资源路径可以没有扩展名。
- 例如 `PlotData.csv` 可以匹配运行时的 `GameData\PlotData`。

普通 CSV 合并规则：

- 第一行表头必须与原表一致。
- 主键列优先识别 `id`、`ID`、`Id`、`编号`、`序号`、`剧情编号`。
- 主键相同则覆盖原行。
- 主键不存在则追加新行。
- 行列数不足时会按空值补齐；多出的非空列会导致该补丁被跳过。

## 7. PlotData 特殊补丁

`PlotData.csv` 是多行剧情块，不是普通单行表：

```text
剧情编号,第一行
,第二行
,第三行
剧情编号2,第一行
```

补丁规则：

- 首列非空的行是剧情块起点。
- 后续首列为空的连续行归入上一块。
- `剧情编号` 已存在时，整块完整替换。
- `剧情编号` 不存在时，整块追加到文件末尾。

`PlotData.csv` 的 `调用函数` 和 `选项` 列也会参与符号 ID 改写，用于把其中引用的 `modXXX` 替换成实际数字 ID。

## 8. 转置 CSV 特殊补丁

当前以下表使用转置表规则：

```text
GameData\HeroSpeTalkText.csv
GameData\HeroNatureTalkText.csv
```

这类表的结构不是“每行一个对象”，而是“首列为字段，首行为对象”。龙之书会使用专门的转置合并逻辑，而不是普通 CSV 行主键逻辑。

制作这类补丁时，优先从导出表复制相关行列作为模板，只保留需要新增或覆盖的对象列。

## 9. 符号 ID

符号 ID 用于解决多个 Mod 新增数据时的数字 ID 冲突。

写法：

```text
mod角色A
mod新剧情001
modMyCustomNpc
```

规则：

- 以 `mod` 开头且长度大于 3 的字符串会被识别为符号 ID。
- CSV 主键中的符号 ID 会作为定义来源。
- 复杂 JSON 中的部分字段可以引用符号 ID。
- 同一个符号 ID 可以在任意位置解析为同一个数字 ID。
- 如果同一个符号 ID 作为 CSV 主键出现在多个补丁文件中，会输出警告。
- 非主键位置只是引用，不会触发重复定义警告。
- 分配结果会写入 `SymbolicFieldReport.json`。

报告路径：

```text
<游戏目录>\DataDump\Latest\SymbolicFieldReport.json
```

当前公开给其他程序集引用的符号 ID API 包括：

- `SymbolicIdService.RegisterExternalReference(...)`
- `SymbolicIdService.TryResolveId(...)`
- `SymbolicIdService.TryResolveIdForSource(...)`
- `SymbolicIdService.TryGetSourceResolution(...)`
- `SymbolicIdService.TryGetSymbolicId(...)`
- `SymbolicIdService.BuildCanonicalSourcePath(...)`
- `SymbolicIdTokenDelimiters.TokenDelimiters`
- `SymbolicIdTokenDelimiters.IsDelimiter(...)`

## 10. 复杂数据导出

导出目录：

```text
<游戏目录>\DataDump\Latest\ComplexData
```

当前导出文件：

```text
WorldPlotEventController_WorldPlotEventDataBase.json
MissionDataController_bountyMissionDataBase.json
MissionDataController_MainMissionDataBase.json
MissionDataController_BranchMissionDataBase.json
MissionDataController_LittleMissionDataBase.json
MissionDataController_TreasureMapMissionDataBase.json
MissionDataController_SpeKillerMissionDataBase.json
```

导出策略：

- 在 `GameController.Start` 后启动一轮导出。
- 等 `WorldPlotEventController` 和 `MissionDataController` 的目标字段都就绪后落盘。
- 每轮先导出原始运行时对象，再应用 JSON 补丁。
- JSON 使用 UTF-8 无 BOM。
- 中文和 `<`、`>` 会直接输出，不写成 `\uXXXX`。

## 11. 复杂 JSON 补丁

补丁目录：

```text
Mods\ModsOfLong\modExample\ComplexData
```

当前支持文件：

```text
MissionDataController_bountyMissionDataBase.json
MissionDataController_BranchMissionDataBase.json
MissionDataController_LittleMissionDataBase.json
MissionDataController_MainMissionDataBase.json
MissionDataController_SpeKillerMissionDataBase.json
MissionDataController_TreasureMapMissionDataBase.json
WorldPlotEventController_WorldPlotEventDataBase.json
```

数组型补丁：

```text
MissionDataController_bountyMissionDataBase.json
MissionDataController_BranchMissionDataBase.json
MissionDataController_LittleMissionDataBase.json
MissionDataController_MainMissionDataBase.json
WorldPlotEventController_WorldPlotEventDataBase.json
```

规则：

- JSON 根节点是数组。
- 数组元素按 `name` 字段匹配。
- `name` 相同则覆盖。
- `name` 不同则新增。

对象整体替换：

```text
MissionDataController_SpeKillerMissionDataBase.json
MissionDataController_TreasureMapMissionDataBase.json
```

规则：

- JSON 根节点是单个对象。
- 补丁会整体替换目标字段。

实现特征：

- 当前不是重建一整份托管对象树后再整体替换。
- 对数组型数据，会尽量原地修改现有 IL2CPP 对象图。
- 因此 UnityExplorer 里看到的运行时对象也能反映补丁结果。

## 12. 剧情与任务数据关系

核心关系：

```text
WorldPlotEventData -> plotID -> PlotData.csv
MissionData -> missionTargetDatas / eventData / plotID -> PlotData.csv
```

定位：

- `PlotData.csv` 是剧情内容表，包含对白、背景、音效、选项等。
- `WorldPlotEventDataBase` 是世界剧情触发规则表。
- `MissionDataController_*.json` 是任务模板数据。
- `MissionData` 接任务时会被 `Clone()` 成运行时任务实例。

更详细的字段解释见 [剧情文件结构](剧情文件结构.md)。

## 13. 常用验证

构建：

```powershell
dotnet build D:\codes\LongYin\TheBookOfLong\TheBookOfLong.sln
```

查看导出目录：

```powershell
Get-ChildItem -Path '<游戏目录>\DataDump\Latest' -Recurse -File
```

查看符号 ID 报告：

```powershell
Get-Content '<游戏目录>\DataDump\Latest\SymbolicFieldReport.json' -TotalCount 300
```

查看相关日志：

```powershell
rg -n "Loaded data patch|Game complex data mod|Game complex data export complete" '<游戏目录>\MelonLoader\Logs'
```
