# 开发者调研指南

本文面向继续开发龙之书的人，目标是快速判断一个功能该从哪里查、如何验证、哪些边界不要轻易打乱。

## 1. 先看运行入口

主入口：

```text
src\TheBookOfLong\MainMod.cs
```

当前初始化顺序：

1. `ModSettings`
2. `ConfigDumpManager`
3. `ModProjectRegistry`
4. `SymbolicFieldManager`
5. `DataModManager`
6. `GameComplexDataPatchManager`
7. `GameComplexDataDumpManager`
8. `Harmony.PatchAll`

如果要调查“为什么某个功能没生效”，先确认它是否在这个顺序中已经初始化。

## 2. 代码目录职责

```text
src\TheBookOfLong
├─ Csv
├─ ComplexData
├─ Mods
├─ Symbolic
├─ UI
└─ MainMod.cs
```

职责：

- `Csv`：原始文本导出、CSV 补丁加载、CSV 合并、特殊 CSV 规则。
- `ComplexData`：场景内复杂对象导出、复杂 JSON 补丁、IL2CPP 对象图访问。
- `Mods`：扫描 `ModsOfLong`、读取 `Info.json`、维护加载配置。
- `Symbolic`：收集、分配、报告 `modXXX` 符号 ID。
- `UI`：MelonPreferences 编辑界面。

## 3. 调查 CSV 功能

优先看：

```text
Csv\ConfigDumpPatches.cs
Csv\ConfigDumpManager.cs
Csv\DataModManager.cs
Csv\DataModManager.Loading.cs
Csv\CsvPatchApplier.cs
Csv\CsvSpecialPatchRules.cs
```

调查路径：

1. `ConfigDumpPatches` 确认挂了哪些游戏方法。
2. `ConfigDumpManager` 确认原始文本如何捕获、命名和写入。
3. `DataModManager.Loading` 确认补丁文件如何从已启用 Mod 中读取。
4. `CsvPatchApplier` 确认普通表如何合并。
5. `CsvSpecialPatchRules` 确认是否走特殊表逻辑。

特殊表：

- `PlotData.csv`：走剧情块合并。
- `HeroSpeTalkText.csv`、`HeroNatureTalkText.csv`：走转置表合并。

常用搜索：

```powershell
rg -n "TryApplyTextPatch|CaptureTextAssetRead|ReadFile|ReadMultiLine|TextAsset.text" src\TheBookOfLong
rg -n "CsvSpecialPatchKind|PlotDataBlock|TransposedTable" src\TheBookOfLong
```

## 4. 调查 ComplexData 功能

优先看：

```text
ComplexData\GameComplexDataDumpPatches.cs
ComplexData\GameComplexDataDumpManager.cs
ComplexData\GameComplexDataPatchManager.cs
ComplexData\GameComplexDataPatchManager.Loading.cs
ComplexData\GameComplexDataPatchManager.ApplyCycle.cs
ComplexData\ComplexPatchExecutor.cs
ComplexData\ComplexJsonValuePatcher.cs
ComplexData\ComplexTypeAccessor.cs
```

关键点：

- 只有一个 `GameController.Start` Patch。
- 这个 Patch 同时启动 ComplexData 导出和补丁应用。
- 补丁应用会等待对应导出轮次完成。
- 目标控制器就绪判断在 `ComplexDataTargets`。
- JSON 到 IL2CPP 对象的转换在 `ComplexJsonValuePatcher` 和 `ComplexTypeAccessor`。

常用搜索：

```powershell
rg -n "GameController.Start|StartNewExportCycle|StartApplyCycle|WaitAndApplyPatches" src\TheBookOfLong
rg -n "TargetDefinitionsByFileName|WorldPlotEventDataBase|MissionDataBase" src\TheBookOfLong
```

## 5. 调查符号 ID

优先看：

```text
Symbolic\SymbolicIdService.cs
Symbolic\SymbolicFieldManager.cs
Symbolic\DelimitedSymbolicIdRewriter.cs
Symbolic\SymbolicIdTokenDelimiters.cs
Csv\PlotDataSymbolicIdResolver.cs
ComplexData\ComplexSymbolicFieldRules.cs
```

关键点：

- `SymbolicIdService` 管最终分配。
- `SymbolicFieldManager` 管引用记录和报告输出。
- CSV 主键里的 `modXXX` 是主要定义来源。
- ComplexData 中的 `plotID` 等字段通常是引用来源。
- 外部 Mod 需要解析 `modXXX` 时，优先使用 `SymbolicIdService.TryResolveId(...)`，不要把解析绑定到某个文件。
- 只有同一个 `modXXX` 作为 CSV 主键出现在多个补丁文件中才会报警；非主键位置是引用。
- `SymbolicFieldReport.json` 是验证分配和引用关系的第一入口。

常用搜索：

```powershell
rg -n "RegisterExternalReference|TryResolveId|TryResolveIdForSource|TryGetSymbolicId|WriteReport" src\TheBookOfLong
rg -n "plotID|json-plotID|SymbolicFieldReport" src\TheBookOfLong
```

## 6. 调查 Mod 加载

优先看：

```text
Mods\ModProjectRegistry.cs
Mods\ModLoadConfigManager.cs
Mods\ModProject.cs
Mods\IModProject.cs
```

关键点：

- `ModProjectRegistry` 统一扫描 `ModsOfLong`。
- `ModLoadConfigManager` 维护 `UserData\TheBookOfLong.ModLoadConfig.json`。
- CSV 和 ComplexData 补丁系统都从注册表拿已启用 Mod 快照。
- 外部 Mod 可以引用公开的 `IModProject` 和 `ModProjectRegistry` 读取当前数据 Mod 信息。

当前公开 API：

```csharp
ModProjectRegistry.GameRoot
ModProjectRegistry.ModsRoot
ModProjectRegistry.ModsOfLongRoot
ModProjectRegistry.Initialize()
ModProjectRegistry.GetEnabledProjectsSnapshot()
```

## 8. 增加新功能时的边界

建议保持这些边界：

- 不要把 Harmony Patch 类当成公共 API。
- 不要让外部 Mod 直接调用补丁执行器。
- 新增 CSV 特例时，集中登记到 `CsvSpecialPatchRules`。
- 新增 ComplexData 目标文件时，集中登记到 `GameComplexDataPatchManager` 的目标定义。
- 新增符号字段时，集中登记到 `ComplexSymbolicFieldRules` 或对应 CSV 解析器。
- 文件变长时优先拆分 partial 文件，不继续堆在单文件里。

外部 Mod 引用龙之书时，优先使用当前公开 API：

```csharp
IModProject
ModProjectRegistry
SymbolicIdService
SymbolicSourceResolution
SymbolicIdTokenDelimiters
```

## 10. 常见判断

CSV 文件没有生效：

- 文件名是否能匹配导出的资源名。
- 表头是否与原表完全一致。
- 主键列是否被正确识别。
- 是否被 Mod 加载配置禁用。

ComplexData 文件没有生效：

- 文件名是否在当前支持列表里。
- JSON 根节点类型是否符合目标规则。
- 数组对象是否有 `name`。
- 是否等到了场景控制器就绪。

符号 ID 没有解析：

- 字符串是否以 `mod` 开头且长度大于 3。
- 是否有 CSV 主键定义来源。
- 是否查看了最新的 `SymbolicFieldReport.json`。
- ComplexData 补丁是否发生在 CSV 符号分配之后。
