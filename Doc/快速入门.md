# 快速入门

本文面向第一次使用龙之书制作数据 Mod 的作者。目标是先跑通“导出数据 -> 找到要改的内容 -> 写补丁 -> 验证结果”这一条完整流程。

## 1. 先启动一次游戏

安装并启动龙之书后，确认这些目录已经生成：

```text
<游戏目录>\DataDump\Latest
<游戏目录>\DataDump\Latest\Data
<游戏目录>\DataDump\Latest\ComplexData
<游戏目录>\Mods\ModsOfLong
```

其中：

- `Data` 保存游戏原始文本配置，主要是 CSV，也包含少量原始 JSON 文本。
- `ComplexData` 保存游戏场景中运行时对象导出的 JSON，例如任务库和世界剧情触发器。
- `ModsOfLong` 是放置数据 Mod 的根目录。

如果找不到某个文件，先确认已经进到游戏主流程。部分复杂数据需要场景对象初始化完成后才会导出。

## 2. 先理解数据分层

制作 Mod 时，先判断你要改的是哪一层：

| 目标 | 优先查看 |
| --- | --- |
| 文本、名称、物品、普通配置表 | `DataDump\Latest\Data\*.csv` |
| 剧情对白、选项、音效、背景 | `DataDump\Latest\Data\PlotData.csv` |
| 任务模板 | `DataDump\Latest\ComplexData\MissionDataController_*.json` |
| 世界剧情触发规则 | `DataDump\Latest\ComplexData\WorldPlotEventController_WorldPlotEventDataBase.json` |
| 任务和剧情字段含义 | `Doc\剧情文件结构.md` |

一个常见误区是把 `PlotData.csv` 当作剧情触发表。它主要保存剧情内容；“什么时候触发这段剧情”通常在 `WorldPlotEventDataBase` 或任务数据里。

## 3. 创建 Mod 目录

在游戏目录下创建：

```text
Mods
└─ ModsOfLong
   └─ modMyFirstMod
      ├─ Info.json
      ├─ Data
      └─ ComplexData
```

`Info.json` 可选，但建议保留：

```json
{
  "Name": "我的第一个数据 Mod",
  "Version": "1.0.0"
}
```

文件夹名必须以 `mod` 开头，龙之书才会识别它。

## 4. 修改普通 CSV

假设导出文件是：

```text
DataDump\Latest\Data\NameData.csv
```

补丁文件应放在：

```text
Mods\ModsOfLong\modMyFirstMod\Data\NameData.csv
```

写补丁时建议从导出的原表复制表头，再只保留需要新增或覆盖的行：

```csv
id,name,desc
modMyNewRow,新名字,新说明
1001,覆盖原有名字,覆盖原有说明
```

规则：

- 表头必须与原表一致。
- 主键相同会覆盖原行。
- 主键不存在会追加新行。
- 主键可以写成 `modXXX`，龙之书会在运行时分配实际数字 ID。

## 5. 修改 PlotData 剧情内容

`PlotData.csv` 是多行块结构。一个剧情 ID 可以占多行，首列为空的行会归到上一条剧情块。

补丁文件路径：

```text
Mods\ModsOfLong\modMyFirstMod\Data\PlotData.csv
```

写法要点：

```csv
剧情编号,其余列保持从导出表复制
modMyFirstPlot,第一行剧情内容...
,第二行剧情内容...
,第三行剧情内容...
```

规则：

- 从导出的 `PlotData.csv` 复制完整表头，不要自己简写表头。
- `剧情编号` 已存在时，整个剧情块会被完整替换。
- `剧情编号` 不存在时，整个剧情块会追加到文件末尾。
- 新增剧情建议使用 `modXXX` 作为剧情编号。

## 6. 修改任务或世界剧情触发器

复杂对象补丁放在 `ComplexData` 目录中。常用文件：

```text
Mods\ModsOfLong\modMyFirstMod\ComplexData\WorldPlotEventController_WorldPlotEventDataBase.json
Mods\ModsOfLong\modMyFirstMod\ComplexData\MissionDataController_MainMissionDataBase.json
```

建议做法：

1. 从 `DataDump\Latest\ComplexData` 复制一个相近对象作为模板。
2. 修改 `name`，避免和原对象冲突。
3. 修改 `plotID`、触发条件、任务字段等必要内容。
4. 对照 `Doc\剧情文件结构.md` 理解字段含义。

数组型复杂数据按 `name` 匹配：

- `name` 相同：覆盖已有对象。
- `name` 不同：新增对象。

在 `MissionData` 和 `WorldPlotEventData` 的 `plotID` 字段中，也可以引用 `PlotData.csv` 里的符号 ID：

```json
[
  {
    "name": "modMyFirstEvent",
    "plotID": "modMyFirstPlot"
  }
]
```

实际补丁中不要只写这两个字段。新增复杂对象时应复制完整对象模板，再按需修改，否则很容易缺字段。

## 7. 调整加载顺序

龙之书会生成：

```text
<游戏目录>\UserData\TheBookOfLong.ModLoadConfig.json
```

其中 `Mods` 数组的顺序就是加载顺序。越靠后的 Mod 越晚加载，覆盖能力越强。

修改该文件后需要完全重启游戏。

## 8. 验证结果

常用检查点：

```text
<游戏目录>\DataDump\Latest\manifest.json
<游戏目录>\DataDump\Latest\SymbolicFieldReport.json
<游戏目录>\MelonLoader\Logs
```

验证建议：

- 看 `SymbolicFieldReport.json`，确认 `modXXX` 被映射成了数字 ID。
- 搜日志中的 `Loaded data patch`、`Game complex data mod`、`Game complex data export complete`。
- 如果 CSV 没生效，先检查补丁文件名、表头、主键列。
- 如果复杂 JSON 没生效，先检查文件名是否是当前支持的导出文件名，数组对象是否有 `name`。
